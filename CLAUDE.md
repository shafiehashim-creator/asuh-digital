# ASUH Digital — panduan projek untuk Claude Code

Platform e-book kanak-kanak Islamik (umur 6–13) oleh ASUH, jenama Galeri Ilmu Media Group.
Pembeli: ibu bapa (Pas Tahunan, e-book single) dan institusi (lesen tahunan untuk tadika, sekolah kebangsaan (SK), sekolah rendah agama, KAFA, tahfiz).
Tagline jenama: **Jom Jadi Baik!**
Rujukan skrin: prototaip ASUH Digital di claude.ai (7 skrin: utama, katalog, halaman buku, harga, bayaran, rak buku, Mod Anak).

## Peraturan kerja (wajib)

- Jangan push ke `main`, deploy ke server, atau jalankan migrasi di production tanpa pengesahan saya dalam chat.
- Jangan sesekali commit rahsia (kata laluan, API key, kredensial cPanel, kunci CHIP). Semua dalam `.env`, dan `.env` mesti ada dalam `.gitignore`.
- Sebelum mula kerja baru, baca semula fail ini dan nyatakan fasa yang sedang dibina.
- Semua teks yang dilihat pengguna ditulis dalam Bahasa Melayu dahulu, dibungkus `__('Ayat BM')`, dan terjemahan Inggerisnya dalam `lang/en.json` (lihat **Dwi bahasa**). Kod, nama jadual dan komen dalam Bahasa Inggeris.
- Setiap fasa mesti ada ujian (Pest atau PHPUnit) untuk aliran bayaran, akses e-book dan pintu ibu bapa.

## Stack

- PHP 8.3 dengan **Laravel 13**. Laravel 11 tidak digunakan kerana sokongan keselamatannya sudah tamat dan Composer menyekatnya atas amaran keselamatan.
- MySQL 8.0 di production (cPanel). SQLite untuk pembangunan dan ujian lokal, jadi migrasi mesti serasi dengan kedua-duanya.
- **Filament 5** untuk panel admin di `/admin`
- Blade, Tailwind CSS dan Alpine.js untuk bahagian awam. Aset dibina secara lokal atau dalam GitHub Actions. **Tiada Node.js di server.**
- PDF.js untuk pembaca e-book dalam pelayar
- Queue: driver `database`, dijalankan melalui cron cPanel (`schedule:run` setiap minit)
- E-mel: SMTP daripada hos cPanel

## Dwi bahasa (BM / English, keputusan pengguna 2026-10-26)

- Terjemahan sebenar (bukan auto-terjemah), dibina berperingkat. **Peringkat 1 (siap):** laman awam (utama, langganan, katalog, halaman buku, tentang kami, polisi, log masuk/daftar, checkout, bayaran, muat naik resit, pilot) dan e-mel resit. **Peringkat 2 (belum):** akaun ibu bapa dan Mod Anak. Panel admin dan portal guru kekal BM.
- Kunci terjemahan ialah ayat BM itu sendiri: `__('Ayat BM')`; locale `ms` memaparkan kunci, `lang/en.json` memetakan ke Inggeris. Komponen `x-field` (label, hint), `x-auth-card`, `x-layouts.app` (title) dan `x-legal-page` menterjemah teks yang dihantar. Ujian `BilingualTest` gagal jika ada `__()` atau label/tajuk dalam fail Peringkat 1 tanpa baris `en.json`; tambah fail baharu ke senarai itu.
- Suis **BM | EN** di header (`/bahasa/{locale}`, `LocaleController`) menyimpan pilihan dalam sesi, kuki `asuh_lang` (1 tahun) dan `users.locale`; middleware `SetLocale` (`App\Support\Locale`). `User` melaksanakan `HasLocalePreference`, jadi e-mel ikut bahasa pengguna. Semasa log masuk (`SyncLocaleOnLogin`), bahasa yang dipilih dalam pelayar disimpan ke akaun; jika tiada pilihan, bahasa akaun dipaparkan. Pengguna boleh tukar balik bila-bila masa.
- Teks Tetapan: `Setting::localized($key)` guna `{$key}_en` jika diisi (headline, subheadline, FAQ, polisi bayaran balik; seksyen "Teks landing page (English)"), jika tidak teks BM. Buku: `title_en`, `synopsis_en` pilihan (`Book::localTitle()`, `localSynopsis()`). Polisi undang-undang Inggeris di `resources/views/legal/en/` dan menyatakan versi BM yang terpakai.
- Nama produk dalam English: Yearly Subscription, Plus Subscription.

Jika beberapa kempen berjalan, yang tamat paling awal dipaparkan. **Affiliate** (keputusan pengguna 2026-10-26): pemegang akaun memohon di `/akaun/affiliate` (cara mempromosi, akaun bank; dibuka oleh suis `affiliates_open`), admin meluluskan di `/admin/affiliate` (e-mel pautan dan kod). **Royalti** (2026-10-26, `/admin/royalti`, Super Admin; `App\Services\Royalties`): model kolam ikut bacaan. ## Bayaran (CHIP dan pindahan bank)

Gateway ialah **CHIP** (chip-in.asia), bukan BCL. Semua kaedah CHIP dibenarkan (FPX, kad, e-wallet). Kunci CHIP (Brand ID, API key, public key webhook) hanya dalam `.env`.

- Setiap pesanan mencipta *purchase* CHIP dengan rujukan pesanan yang unik.
- Pengaktifan Pas **hanya melalui webhook CHIP** yang tandatangannya disahkan, bukan melalui halaman redirect selepas bayaran.
- Webhook mesti idempotent: rujukan yang sama tidak boleh mengaktifkan pas dua kali. Log setiap panggilan webhook.
- Aliran CHIP (dibina 2026-10-24): callback `POST /webhooks/chip` disahkan dengan `X-Signature` (RSA-SHA256, kunci awam dari `GET /public_key/`), kemudian server **bertanya semula** `GET /purchases/{id}/` dan hanya mengaktifkan pas jika status `paid`, jumlah dan mata wang sepadan, dan `is_test` sepadan dengan `CHIP_TEST_MODE`. Semua pengaktifan melalui `App\Services\PaymentProcessor::markPaid()`.
- CHIP menolak URL callback yang mempunyai nombor port, jadi callback hanya sampai di server sebenar (bukan `localhost:8000`).
- Bayaran yang sampai **selepas tempahan luput tetap dihormati** (keputusan pengguna): pas diaktifkan walaupun kiraan slot terlebih sedikit. Admin boleh kenal pasti kes ini kerana `paid_at` lebih lewat daripada `reserved_until`.
- **Pindahan bank:** pembeli muat naik resit, pesanan kekal `pending`, dan hanya `admin` boleh klik **Sahkan bayaran**. Rekod siapa yang mengesahkan dan bila. Butiran bank ialah tetapan admin.
  - Resit (JPG/PNG/WEBP/PDF, maks 5 MB) disimpan dalam `storage/app/private/receipts` dan hanya dipaparkan kepada `admin` melalui `/admin/resit/{rujukan}`.
  - Resit yang dihantar mengekalkan slot sehingga admin membuat keputusan. Resit untuk tempahan yang sudah luput tetap diterima (selaras dengan dasar menghormati bayaran lewat).
  - Admin boleh **Tolak** dengan sebab (dilog); slot dilepaskan dan pembeli boleh menghantar resit baharu. Pesanan dalam panel admin adalah baca sahaja.
- **Caj pemprosesan CHIP dibayar pembeli** (keputusan pengguna 2026-10-26): di halaman bayaran pembeli memilih **FPX**, **E-wallet dan DuitNow QR** atau **Kad** (`App\Enums\ChipMethod`), setiap satu dengan jumlah termasuk caj. Caj = amaun tetap + peratus (`chip_fee_{fpx,ewallet}_{fixed,percent}` di Tetapan, lalai 0; `App\Services\Chip\ProcessingFee`, dibundarkan ke atas). **Kad sentiasa tanpa caj** (peniaga di Malaysia tidak boleh mengenakan surcaj kad) dan pindahan bank tanpa caj. Caj disimpan dalam `orders.processing_fee_sen` dan `orders.chip_method`; `amount_sen` kekal harga produk (laporan jualan tidak mengira caj) dan `Order::totalSen()` ialah jumlah dibayar, yang disemak dalam callback. Purchase CHIP mempunyai baris caj berasingan dan `payment_method_whitelist` untuk kaedah dipilih (dipadankan dengan `GET payment_methods/` brand, cache 1 jam). Menukar kaedah membatalkan purchase lama (`POST purchases/{id}/cancel/`) sebelum mencipta yang baharu; jika pembatalan gagal, purchase lama dikekalkan.
- Tiada caj berulang automatik. **Langganan Bulanan** (keputusan pengguna 2026-10-26): RM14.90 sebulan untuk e-book dan Plus Bulanan (harga di Tetapan), dibayar manual setiap bulan; tahunan kekal pilihan utama. Checkout `/beli/langganan` dan `/beli/langganan-plus` memaparkan kad **Tahunan** (dipilih lalai, "Paling berbaloi · Jimat 45%") dan **Bulanan** (`tempoh=tahunan|bulanan`, `App\Enums\BillingPeriod`, `App\Services\SubscriptionPlans`, `yearlySavingPercent`). Bulanan dijual selepas early bird tamat, sama seperti tahunan harga biasa; halaman jualan dan laman utama memaparkan "Jimat X% berbanding bayar bulanan" dan pautan kecil ke bulanan (`x-monthly-option`). Kod sekolah dan naik taraf ke Plus untuk tahunan sahaja; kupon "Semua produk" atau "Langganan bulanan" (`PromoProduct::Monthly`) terpakai. Bila pelanggan bulanan membeli tahunan, tahunan bermula sebaik bulan semasa tamat. Akaun memaparkan "Tukar ke tahunan" dan "Perbaharui sebulan lagi". `php artisan asuh:renewal-reminders` setiap hari 10:00 pagi menghantar e-mel 3 hari sebelum langganan bulanan tamat (sekali, `passes.renewal_reminded_at`, tidak jika sudah diperbaharui).
- **Tambah manual oleh admin** (2026-10-26): di halaman pelanggan (`/admin/pelanggan/{id}`), butang **Tambah langganan** dan **Tambah e-book** (`App\Services\ManualGrants`) mencipta pesanan dengan kaedah `manual` ("Manual (oleh ASUH)"), jumlah (0 untuk percuma), sebab dalam `orders.admin_note`, dan admin yang memberi dalam `confirmed_by`; pengaktifan melalui `PaymentProcessor::markPaid()` (resit e-mel boleh dimatikan). Kaedah `manual` tidak boleh dipilih semasa checkout. Butang **Pelanggan baharu** mencipta akaun ibu bapa dan menghantar e-mel untuk menetapkan kata laluan.
- Hantar resit melalui e-mel selepas status pesanan bertukar kepada `paid`. Maklumat syarikat pada resit (nama, SSM, alamat, SST) ialah tetapan admin.

## Skop Fasa A (dipersetujui 2026-10-24)

- Pre-order **Pas Tahunan harga early bird RM79**, bayar penuh, terhad **100 slot**. Slot ditempah sementara (~30 minit) semasa bayaran dan dilepaskan jika tidak dibayar.
- Pas 12 bulan bermula **selepas bayaran disahkan**. Peraturan tarikh mula boleh ditukar di admin (contohnya kepada tarikh launch).
- Pembeli **cipta akaun semasa checkout** (e-mel dan kata laluan, pengesahan e-mel, lupa kata laluan). Sejak 2026-10-26 ibu bapa juga boleh mendaftar sendiri di `/daftar` (Fortify registration, nama, e-mel, telefon, kata laluan dan persetujuan PDPA; dihadkan 5 pendaftaran/minit setiap IP oleh `ThrottleRegistrations`). Satu pelayar satu log masuk: pengguna yang sudah log masuk dan membuka `/login`, `/daftar`, `/admin` (bukan staf) atau `/guru` (bukan guru) dibawa ke **Tukar akaun** (`/tukar-akaun`, `SwitchAccountController`) untuk log keluar dan log masuk akaun lain, bukan 403. Akaun ibu bapa (2026-10-26, struktur ala papan pemuka LearnAI) ialah menu tepi (`x-layouts.account`; cip menu di telefon) dengan halaman **Ringkasan** `/akaun` (sapaan dengan satu butang utama, 4 kad statistik, Sambung membaca dengan bulatan % halaman, anak-anak minggu ini), **Rak buku saya** `/akaun/rak`, **Anak-anak** `/akaun/anak` (profil dan PIN), **Pencapaian** `/akaun/pencapaian` (minggu ini dan lencana setiap anak, `App\Services\FamilyProgress`, dikongsi dengan laporan mingguan), **Langganan dan pesanan** `/akaun/langganan` (status, pesanan, bayaran) **Profil dan keselamatan** `/akaun/profil` (maklumat, kata laluan, laporan mingguan) dan **Panduan** `/akaun/panduan` (keputusan pengguna 2026-10-26: peta perjalanan 5 langkah, senarai semak keluarga sendiri, dan langkah bergambar dengan lukisan telefon `x-guide.phone` untuk tambah anak, PIN, Mod Anak, membaca/kuiz/lencana, video dan kawalan menonton (bila video dibuka), keluar Mod Anak, pantau kemajuan, pasang app; dipaut dari kad di Ringkasan); satu kad tawaran (langgan / naik taraf Plus / perbaharui) ikut status.
- Maklumat pembeli: nama, e-mel, telefon, negeri, bilangan anak, kumpulan umur anak, dan persetujuan PDPA.

- Halaman notis privasi dalam BM, dan persetujuan ibu bapa semasa mendaftar.
- Ibu bapa boleh memadam profil anak dan semua data bacaannya.

## Git dan deploy ke cPanel

- Repo GitHub **peribadi**. Cawangan `main` untuk production dan `develop` untuk kerja harian. Hanya `main` yang dideploy.
- **Tiada staging untuk Fasa A.** Sebelum launch, production (`asuh.galeriilmu.com.my`) diuji dengan CHIP mod ujian (test mode), kemudian kunci ditukar kepada live dan pesanan ujian dikosongkan. Staging (`staging-asuh.galeriilmu.com.my`) ditimbang semula sebelum Fasa B.
- Struktur server: kod di `/home/galeriil78/asuh-app` (di luar `public_html`) dengan `releases/<masa>-<sha>/`, `current` (symlink ke release aktif) dan `shared/` (`.env` serta `storage/`). `public_html/asuh.galeriilmu.com.my` ialah symlink ke `asuh-app/current/public`. Laman utama syarikat berada dalam akaun cPanel yang sama, jadi jangan sentuh `public_html` yang lain.
- Panduan penuh dan senarai tugasan pengguna: `docs/DEPLOY.md`. Skrip server: `scripts/deploy/activate-release.sh` dan `rollback.sh`, diuji dalam CI melalui raptai deploy sebelum deploy sebenar.
- DNS di Cloudflare: rekod A `asuh` dalam mod DNS only (awan kelabu) supaya AutoSSL cPanel berfungsi.
- Deploy melalui **cPanel Git Version Control** (pengguna sudah biasa dengannya). SSH dari luar ke server tidak tersedia (diuji 2026-10-24), jadi GitHub tidak pernah masuk ke server. Push ke `main` menjalankan ujian dan raptai, kemudian GitHub Actions membina release lengkap (`vendor` dan aset, kerana tiada Node di server) dan commit ke cawangan `deploy-build` (tanpa force-push). Cron auto-deploy di server (`scripts/deploy/auto-deploy.sh`, setiap 5 minit) menarik release baharu dan menjalankan `cpanel-deploy.sh` sendiri. Kelulusan pengguna dalam chat sebelum push ke `main` ialah satu-satunya pintu, jadi JANGAN push ke `main` tanpa kelulusan itu. Cara manual sandaran: `git pull` di Terminal + *Deploy HEAD Commit* (butang *Update from Remote* cPanel tidak guna alias SSH); `.cpanel.yml` menjalankan `scripts/deploy/cpanel-deploy.sh`, yang menyalin klon ke release baharu dan memanggil `activate-release.sh` (`migrate --force`, `PlanSeeder`, `optimize`, `filament:optimize`, kemudian tukar `current` secara atomik).
- Document root domain mesti menghala ke folder `public/`.
- Tiada rahsia dalam GitHub. Klon cPanel menarik repo peribadi menggunakan kunci SSH server (kunci akaun atau deploy key baca sahaja). Rahsia aplikasi hanya dalam `~/asuh-app/shared/.env`.
- PHP CLI lalai server ialah 7.3; sentiasa guna `/opt/cpanel/ea-php83/root/usr/bin/php` untuk artisan, deploy dan cron.
- Pasang cron: `* * * * * cd /home/galeriil78/asuh-app/current && /opt/cpanel/ea-php83/root/usr/bin/php artisan schedule:run >> /dev/null 2>&1`
